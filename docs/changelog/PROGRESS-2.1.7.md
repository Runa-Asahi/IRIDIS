# 2.1.7（vc185，2026-10-22）

release/2.1.7 = feat/ux-217（已含 fix/agent-answer）合并 feat/imagegen，再加「识图清晰度」。

## 智能体 / 聊天
- 修复：智能体调用搜索等工具后有时不出回答（新闻搜索一片空白）；现在工具结束后一定会给出最终回答。
- 模型加载中发送消息：不再报错，消息会等这次加载完成后用该模型回答；取消加载会释放等待中的消息。
- 加载可取消：模型选择面板的加载区新增「取消」，排队中的加载不会再开始；点空白处只关闭面板。
- 点按图标加载「默认模型」：空对话页中间的图标可点，加载时有脉冲动画，完成后显示 ✓ 和模型名；设置 › 模型与后端 新增「默认模型」（未设置 = 上次使用的模型）。
- 生成中也能发送：发「停 / 等等 / 不对 / 算了 / 取消 / stop」等或长按发送选「打断并发送」，会停下当前回答并开始新一轮；其他内容作为「补充」——智能体在下一步前读到（附在最新的用户侧消息上，KV 前缀不变），普通聊天显示为「待回复」气泡并在当前回答后接着回答；可排队多条，点一下取消。

## API
- 自定义 API Key：可编辑、显示/隐藏、随机生成、复制、保存；鉴权同时接受 `Authorization: Bearer` 和 `x-api-key`。

## 语音
- 语音对话可以用工具：开了智能体，或判断为需要联网/指令类的话，会走智能体流程；第一次调用工具前固定说一句「我查一下」，只朗读最终回答；需要确认的工具在通话中会婉拒（「要你在屏幕上确认」）。
- 朗读更自然：去掉 Markdown、代码（改说「代码已放在屏幕上」）、链接、表情、表格，最多读 3 句，过滤「作为 AI…」之类的套话；语音提示从系统提示移到每轮附注，不影响 KV 复用。
- 修复：键盘打开时长按语音胶囊会被误判为上滑取消（滑动距离改用窗口坐标计算）。

## 识图清晰度（新）
- 非 MNN 引擎（llama.cpp / LiteRT / GenieX）发给视觉模型的图片默认长边由 1024 → 512 px，视觉编码和预填充明显变快。
- 设置 › 模型与后端 新增「识图清晰度」：快速 384 / 标准 512（默认）/ 清晰 1024。MNN 仍最多 512 px（清晰也按 512），选快速时用 384。改完下一张图生效，无需重新加载。
- 缩放后的图片缓存按尺寸分别命名（`.vis384.jpg` / `.vis512.jpg`，1024 沿用旧名 `.vis.jpg`）。
- 新增设置字段 `visionSide`（默认 512），旧设置文件读入为「标准」；V178Test 已登记。

## 生图（feat/imagegen）
- 新增「生图」页（侧栏入口）：模型档位、正/反向提示词、图生图、尺寸 / 步数 / CFG / 种子；结果可保存、分享、「发到聊天」；历史网格；「生图自检」。图片存于工作区 `images/IMG_*.png`，PNG 内写入生成参数。
- 模型下载：HF / 镜像断点续传、S3 下载，sd15-qnn 压缩包边下边解压（显示「解压中」），可下载 / 取消 / 删除并显示进度。
- 智能体工具 `generate_image`（生图分组）：只有装了生图模型时才出现在工具列表里，系统提示预算仍 ≤ 600 token；生成的图片作为步骤缩略图显示，并附在回答末尾。
- QNN NPU 引擎（sd15-qnn）：`libiris_imagegen.so` 通过 dlopen 调 QNN HTP，加载 context binary；流程 CLIP → 文本编码 → 反量化/量化 → Euler + CFG（UNet ×2）→ VAE → PNG；设备探测（后端、CDSP 架构、unsigned PD），探测失败自动退回占位引擎；在生图页生成前会先卸载聊天模型以腾出内存。
- **未真机验证**：QNN 生图流程只在 JVM 上用假计算图测过，在 Redmi K90（SM8750）上能否加载、速度、出图质量都还没验证；MNN 版生图模型只有下载，没有推理引擎。

## 没做 / 跳过
- 多轮对话中「已发送过的图片不再重复预填充」：检查后跳过。新的一轮用户消息本来就只带最新那条消息的图片，旧图片只留文字说明；LiteRT 在历史前缀相同时只发最后一条消息、不会重发图片。剩下的情况是智能体同一轮的多步：MNN 带图时必须整段重置预填充（它的增量路径对视觉 token 的 mRoPE 位置是错的），GenieX VLM 每次按完整模板带图；要省掉这部分需要改原生层，风险大，留待以后。
